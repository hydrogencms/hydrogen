# starter

The page-builder starter project: a block-based schema (`hero`, `richText`, `cards`, `callout`, `image` and the built-in
`shared` block, with design tokens in `schema/tokens.yaml`), `page`, `landing`, `post` and `sharedBlock` (a reusable block set) types, a `siteSettings`
singleton, one `main` site and two web channels (`en`, `de`) on the path prefixes `/en` and `/de`. The frontend owns
`/blog` and `/api`; the CMS routes the pages and gives posts their URLs through the channel's `links:` pattern. It
exercises the `pages` module, blocks and tokens, translations, shared blocks inlined by delivery, and the committed
`fixture/` export. This is the CMS side of the frontend starters in `packages/starters/*`, of the adapter conformance
suite, and (as schema and fixture) of `examples/fullstack`. Start here for a block-based site on any frontend.

## Prerequisites

- Go 1.26 or later.
- `make admin` once from the repo root (needs Node): the admin is embedded and `admin/dist` is not committed.
- Node only for a frontend (for example `packages/starters/next`).
- Postgres is optional: `make db-up`, then
  `DATABASE_URL=postgres://hydrogen:hydrogen@localhost:5436/hydrogen?sslmode=disable`.

## Run it

From the repo root:

```sh
cd examples/starter
mkdir -p .work
go build -o .work/starter .
.work/starter migrate
.work/starter import fixture
.work/starter serve
```

`import fixture` loads the committed export (13 items, the page tree and routes). Defaults: `LISTEN_ADDR=:8080`,
`DATABASE_URL=sqlite:.work/hydrogen.db`, `SCHEMA_DIR=schema`, `MANAGE_TOKEN=dev-token`,
`STARTER_FRONTEND=http://localhost:3000` (where the frontend lives: canonical URLs and preview links are built from it).
It runs in the dev environment: the manage token is accepted from loopback only and the preview secret is derived from
it. Sign in at `http://localhost:8080/admin` with the `#setup=` link the server logs, or run
`HYDROGEN_ADMIN_PASSWORD=change-me-please .work/starter users:create-admin admin`.

## Try it

```sh
D=localhost:8080/api/deliver/v1
curl -s "$D/tree?channel=en&depth=2"                                   # the English navigation
curl -s "$D/route?channel=en&url=http%3A%2F%2Flocalhost%3A3000%2Fen%2Fabout"   # a URL resolved to its page
curl -s "$D/collections/post/items?channel=en&limit=2"                 # posts, with url and links
curl -s "$D/tree?channel=de&depth=1"                                   # the German navigation
```

- In the admin, open a page and edit its blocks; the block types and tokens are
  defined in `schema/blocks.yaml` and `tokens.yaml`; a `sharedBlock` item is reused by reference.
- Run a frontend against it: `packages/starters/next` (and the SvelteKit, Nuxt and Astro starters) read this project.
  Their READMEs give the steps; set `STARTER_FRONTEND` to the frontend's origin first.
- `examples/fullstack` serves the same schema and fixture as a website from the Go binary.

## Test, fixture and reset

`go test ./...` runs the project on SQLite and, when a database is up (`make db-up`), on Postgres. `make
starter-next-e2e` runs the Next starter against it, and `make conformance` every frontend; run e2e scripts one at a
time. To reset, delete `.work/hydrogen.db` (and its `-shm` and `-wal` files, if present) and import again.

## Gotchas

- The fixture is generated by `tools/fixture`. After changing `schema/`, run `make starter-fixture` from the repo root
  and commit the result with the schema; `examples/fullstack` and the conformance suite depend on it.
- `gen/` is generated code (`hydrogen generate`); never edit it by hand.
- `import` expects an empty database; reset before importing again.
